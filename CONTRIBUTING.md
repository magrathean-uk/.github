# Contributing

This is the default contribution policy for Magrathean UK repositories without their own
`CONTRIBUTING.md`. Follow the target repository's own instructions and licence first.

External contributions are accepted only for public repositories under a permissive or
copyleft licence, and only under that repository's published terms. Proprietary repositories
do not accept outside code. Teslatlas Hub and bmwatlas Hub are maintained only by their owner;
see each repository's own `CONTRIBUTING.md` for its contributor terms.

## Before making a change

1. Read the README and any instructions relevant to the files you will change.
2. Search existing issues and pull requests.
3. Open a proposal before a substantial change to behaviour, architecture, dependencies,
   storage, protocols or the user interface.

Keep credentials, personal or customer data, production configuration and private licensed
assets out of contributions and examples.

## Prepare and verify

Keep a change focused and explain the problem it solves. Use the repository's documented
verification commands, and add or update tests where a test suite exists. Update the
documentation the change affects.

## Licensing and sign-off

Licensing of contributions is explained in [LEGAL.md](LEGAL.md). In short: you license your
contribution under the target repository's own licence, and you confirm you have the right to
do so. Sign off every commit:

```text
git commit -s
```

## Pull request evidence

Describe the problem, the approach and the affected behaviour. Include verification commands
and their results, and any skipped checks. Note security, privacy, licensing, dependency and
compatibility effects where relevant. Follow the [code of conduct](CODE_OF_CONDUCT.md). Report
a vulnerability privately through [SECURITY.md](SECURITY.md), never in a public issue or pull
request.
